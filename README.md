# KPM MOTION — Keep People Moving

A fresh, premium black / blue / red product website for a South African digital design brand.

## Quick start (Windows, VS Code)

1. Extract `KPM_MOTION_Full_Rebuild.zip`.
2. Open the `KPM-MOTION-NEXT` folder in VS Code.
3. Right-click `index.html` and choose **Open with Live Server**. If you do not use Live Server, open the file in a browser, but PWA install/offline behaviour needs a local server or HTTPS.
4. Select **ENTER EXPERIENCE** to hear the swoosh and browser-generated spoken welcome, or **ENTER SILENTLY**.
5. Explore services, the 3D scene, pricing, configurator, demos, assistant and contact actions.

### Important sound behaviour

Browsers (especially iPhone Safari) usually prohibit audible autoplay before a tap. The intro therefore requires the visitor to tap **ENTER EXPERIENCE** for the swoosh and spoken "K P M Motion. Keep people moving." This is a browser restriction, not a broken audio file. The swoosh is a bundled MP3. The calm voice is generated by the visitor's browser/operating system with a preference for available female English voices; the exact voice and even voice support vary by device. "ENTER SILENTLY" is always available.

## Publish on GitHub Pages (simple manual upload)

Create/open your KPM MOTION repository on GitHub. In the repository root, upload the following **individual root files** from `KPM-MOTION-NEXT` (not the containing folder):

- `index.html`
- `style.css`
- `app.js`
- `scene.js`
- `kpm-motion-logo.webp`
- `kpm-swoosh.mp3`
- `icon-192.png`
- `icon-512.png`
- `manifest.webmanifest`
- `sw.js`

You do **not** need to upload `optional-ai-backend`. It is a separate optional server project. Go to **Settings → Pages → Deploy from a branch → main / (root)**. Wait for GitHub to publish. The website can also work as an installable web app when served over HTTPS; offline support applies to the cached site shell. Online 3D requires an internet connection; the CSS scene remains when 3D cannot load.

If an older service worker continues to display the previous website after you upload new files, refresh the site and close/reopen the installed app. If necessary, unregister the old service worker for your KPM site and reload.

## How the website assistant works today

The default KPM guide is a locally running **rule-based assistant**: it understands many questions about purpose, packages, 3D, timelines, domain/hosting, design, and contacting KPM. It does not send messages to a paid AI service and cannot respond intelligently to arbitrary queries like ChatGPT. It should never be described to customers as full generative AI until the backend is actually connected.

## Optional: enable real conversational AI (not required to launch)

The `optional-ai-backend` folder contains a Cloudflare Worker example that uses the OpenAI Responses API and Cloudflare Turnstile plus rate limits. **It is not deployed or active by default.** Using the OpenAI API may incur charges separate from ChatGPT plans.

1. Create an OpenAI API account/key with appropriate spending controls and a Cloudflare account.
2. In Cloudflare Turnstile, create a widget for your GitHub Pages hostname and obtain a **public site key** and **private secret**.
3. Open `optional-ai-backend/wrangler.toml` and replace `https://YOUR-USERNAME.github.io` with the **exact origin** of your public site (scheme + hostname, without repository path or trailing slash). For an own domain use that domain's origin.
4. In VS Code, open a terminal inside the `optional-ai-backend` folder and run:

   ```powershell
   npx wrangler login
   npx wrangler deploy
   npx wrangler secret put OPENAI_API_KEY
   npx wrangler secret put TURNSTILE_SECRET
   npx wrangler deploy
   ```

   Each `secret put` command prompts you to paste the secret. Do not publish the secret or API key in a website file or public repository.

5. In `index.html`, change the configuration near the top from:

   ```js
   window.KPM_CONFIG={aiEndpoint:"",turnstileSiteKey:""};
   ```

   to your deployed worker URL **including `/chat`**, and your public Turnstile site key:

   ```js
   window.KPM_CONFIG={
     aiEndpoint:"https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev/chat",
     turnstileSiteKey:"YOUR_PUBLIC_TURNSTILE_SITE_KEY"
   };
   ```

6. Upload the changed `index.html` and test the assistant on the published website. The assistant will request Turnstile verification before paid AI responses. If it fails, it falls back to local answers. **Do not enable paid AI publicly without confirming the protection, rate limits, API spend limits, and model response safety.** Rate limits are approximate and do not guarantee a hard spending cap. The demo backend has not been deployed to your own accounts by this build.

The 3D scene imports Three.js from a CDN, and Google Fonts are loaded online; all other standard website assets live together in this one folder. For complete offline 3D operation, Three.js would have to be saved locally and the module import updated.

No login, customer database, invoice generation or secure admin portal is implied by the site demos. The storefront is a **service offering**, not a live store accepting payments. The website is a front-end marketing website; send quotations through WhatsApp and verify customer scope personally.
